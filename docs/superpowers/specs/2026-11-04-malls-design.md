# 백화점·쇼핑몰 아이 행사 — 설계

작성일 2026-11-04. 브레인스토밍 대화에서 정한 것을 정리했다. "사용자 결정"은 사용자가 말한 것이고, "Claude 판단"은 대화에서 알렸거나 문서에서 처음 정한 기본값이다(사용자 확인 전).

## 1. 왜 만드나

사용자는 "이번 주 의왕 타임빌라스에서 텔레토비 팝업스토어가 열린다"는 소식을 인스타에서 우연히 봤다. 수원 근처 백화점·쇼핑몰의 캐릭터 팝업·키즈 공연·아이 옷 행사는 매장마다 따로 공지되어 한 곳에서 볼 수 없다. 지금 `events.json`에는 스타필드 수원 '이벤트' 목록(별마당 키즈 공연 등)만 들어온다.

이 기능은 **수원 근처 백화점·쇼핑몰의 아이 대상 행사**를 매일 자동으로 모아 사이트와 인스타 소재로 쓴다.

## 2. 목표 / 비목표 / 실패 기준

목표
- 매일 05:00 빌드 때 아래 매장의 공식 행사 목록을 자동으로 받는다. 사람이 손으로 넣지 않는다 (사용자 결정 "매일 자동으로")
- 공식 목록에 없는 팝업(예: 스타필드 수원 MLB키즈 체험 팝업)은 뉴스 기사로 채운다 (사용자 결정 "뉴스도 조사")
- **사이트에 '백화점' 탭**을 하나 더 만들고, **인스타용 파일 `malls.json`**도 따로 쓴다 (사용자 결정 "둘 다")

남기는 것 (사용자 결정)
- 아이와 가서 보고 노는 것: 캐릭터 팝업(텔레토비, 52토이즈, 캐릭터존), 곤충·파충류 팝업, 키즈 공연·체험

비목표
- 어른 브랜드 할인·팝업(아웃도어 다운자켓전, 골프, 명품, 화장품, 가구·가전), 카드·사은·멤버십 혜택, 식품·식당 입점은 넣지 않는다 (Claude 판단, 사용자 결정 범위에서 도출)

실패 기준 (이렇게 되면 기능이 돌아가도 실패)
- 탭이 어른 브랜드 할인·카드 혜택으로 채워진다. 롯데 의왕점 하나만 해도 하루 목록이 68건이고 대부분 어른 대상이다
- 끝난 행사가 보인다
- 기사에 없는 날짜·장소를 AI가 지어낸다
- 매장 하나가 실패해서 사이트 빌드 전체나 다른 매장이 같이 빠진다

## 4. 처리 규칙

**지점 맞추기**: 롯데 목록에는 다른 지점 행사(`일부 지점`, `전점`, `백화점 잠실점`)가 섞여 나온다. 지점명이 그 매장인 항목만 남긴다 (Claude 판단). 같은 행사가 수원·평촌 양쪽에 있으면 매장별로 따로 둔다.

**기간**
- 시작·끝 날짜가 없거나 읽히지 않으면 뺀다. `OPEN`처럼 끝이 없는 것은 입점 소식이라 뺀다 (Claude 판단)
- 롯데 날짜에는 해가 없다. 오늘 기준으로 해를 채우고, 끝이 시작보다 앞이면 끝을 다음 해로 본다 (기존 `starfield.parse_dates`와 같은 생각)
- 사이트: 기존 규칙 그대로. 오늘~이번 주 일요일에 걸치는 것, 30일 넘는 것은 '상시'
- `malls.json`: 오늘~14일 뒤에 걸치는 것 (Claude 판단: 인스타 축제 글이 14일 전부터 올리는 것과 맞춤)

**아이 대상 고르기** (Claude 판단, 사용자는 남길 범위에만 결정)
1. 규칙으로 먼저 뺀다: 카드·무이자·사은·캐시백·멤버십·주차·세차·입점·약국 등
2. 규칙으로 먼저 남긴다: 제목·브랜드·장소에 키즈·아동·유아·베이비·주니어·캐릭터·토이·장난감·레고·체험·곤충·공룡·텔레토비 등, 또는 장소가 아동관·아동행사장
3. 나머지는 Gemini에게 "8세 이하 아이 또는 아이를 데려간 부모가 갈 이유가 있는 행사인가"와 `kind`(play/shop)를 한 번에 묻고, 결과를 항목 id로 `state/`에 캐시해 같은 항목을 다시 묻지 않는다. 리틀티니·미니도우처럼 이름만으로는 아이 브랜드인지 모르는 경우를 위해서다. 판단 근거는 제목·브랜드·층·장소 글자뿐이고, 모르면 뺀다
4. Gemini 호출 자체가 실패한 항목은 그날만 빼고 캐시하지 않는다. 다음 날 다시 묻는다
5. `kind`: 규칙으로 남긴 것은 팝업·체험·공연·전시·캐릭터 낱말이 있으면 `play`, 할인·프로모션·신상품이면 `shop`. 둘 다 아니면 Gemini 결과를 따른다

**뉴스**
- 검색어는 매장 이름 × (팝업, 키즈, 체험)으로 한다 (예: "타임빌라스 의왕 팝업", "스타필드 수원 키즈")
- 기존 `naver.py`처럼 기사 요약문에서 Gemini가 행사(매장·제목·시작·끝·장소)를 뽑고, 시작 날짜가 기사 글자에 실제로 있을 때만 쓴다(`naver.mentions`). 매장은 위 7곳 중 하나여야 한다
- 링크는 기사 원문으로 건다

**중복**: 같은 매장이고 기간이 겹치며 제목의 브랜드/핵심 낱말이 같으면 하나로 합친다. 공식 목록 쪽을 남긴다(링크·층 정보가 정확하다). 뉴스 기사로 MLB키즈처럼 공식 목록에 없는 것만 추가된다.

**실패 처리**: 매장·뉴스 하나가 실패해도 나머지는 계속한다(기존 `build.run`의 출처별 try와 같음). 이 기능 전체가 실패해도 기존 사이트 빌드는 그대로 나가고, `malls.json`은 지난 파일을 둔다(`festivals.write`와 같은 방식).

## 5. 사이트 '백화점' 탭

- 기존 탭(전체 / 수원 / 동탄 / 용인 / … / 의왕) 줄에 '백화점' 탭을 더한다. 백화점 행사는 매장이 있는 시 탭이 아니라 이 탭에만 들어간다. '전체' 탭에는 포함한다 (Claude 판단)
- 탭 안 모양은 다른 탭과 같은 카드 목록(날짜별 + 맨 아래 상시). 장소 줄에 매장 이름을 앞에 붙인다: `타임빌라스 의왕 · 잔디광장` (Claude 판단, 대화에서 알림: "지금 동네 탭과 똑같은 카드 목록으로 가고 매장 이름만 붙인다")
- 카드는 누르면 공식 상세 페이지(없으면 매장 행사 목록 페이지) 또는 기사 원문으로 간다
- 탭 순서와 위치는 빌더 몫

## 6. 인스타용 `malls.json`

- 위치: 저장소 루트 `malls.json` (`festivals.json` 옆). 커밋 대상 여부는 `festivals.json`과 같게
- 형태: `{"updated": "YYYY-MM-DD", "malls": [ … ]}`. 항목 필드: `id`, `source`(`lotte`/`starfield`/`hyundai`/`ak`/`news`), `mall`(예 `타임빌라스 의왕`), `title`, `brand`, `start`, `end`, `place`(층·장소), `address`(매장 주소), `url`, `kind`(`play` 보고 노는 것 / `shop` 옷·용품 할인)
- `kind`를 나누는 이유: 인스타 글은 텔레토비 팝업 같은 'play'를 앞세우고 할인은 뒤에 둘 수 있게 (Claude 판단)
- 인스타 쪽(`~/Documents/ai-hub/content-factory/automation/ig/content.py`) 변경은 이 저장소 밖이다. 지금 `content._gg_theme`에 있는 '쇼핑몰 묶음'(스타필드·백화점 등 서로 다른 곳 2개 이상)이 `events.json` 대신 또는 함께 `malls.json`을 읽게 하는 것은 **별도 작업**으로 한다. 이 문서의 범위는 `malls.json`을 매일 쓰는 데까지다

## 7. 기존 코드와의 관계

- **실행 위치** (Claude 판단, 빌더 검토에서 발견): 매일 05:00 launchd가 도는 것은 `deploy.py`이고, `deploy.py`는 `build.run`만 부른다. `build.py`의 `__main__`은 타지 않는다. 그래서 `__main__`에 붙어 있는 `festivals.write`는 매일 돌지 않고, `festivals.json`의 `updated`가 2026-11-02에서 멈춰 있다
  - 백화점 행사 수집은 `build.run` 안에서 한다(사이트 탭에 필요). `malls.json` 쓰기도 그 결과로 같은 실행에서 한다
  - `festivals.write` 호출도 `__main__`에서 `deploy.py`(또는 `build.run`) 쪽으로 옮겨 매일 돌게 한다. 같은 버그라서 이번에 같이 고친다
  - `malls.json`·`festivals.json` 쓰기가 실패해도 `deploy.py`는 실패로 끝내지 않는다. 빌드 결과의 `errors`와 로그에만 남긴다(사이트 배포는 계속)
  - 두 파일은 git에 올리지 않는다(`PUBLISHED`에 넣지 않음). 인스타는 로컬 경로 `~/Documents/suwon-kids/*.json`을 읽는다
- **`events.json`에는 넣지 않는다** (Claude 판단): `events.json`은 인스타 `content.py`가 읽어 해시태그(`area`)와 '쇼핑몰 묶음' 주제를 만든다. 백화점 행사를 기존 `events`/`long` 배열에 섞으면 인스타 글이 오늘부터 바뀐다. 백화점 행사는 HTML 탭과 `malls.json`에만 쓴다
- 데이터 모양: 사이트 쪽은 기존 `Event`로 바꿔 `area='백화점'`처럼 다룰 수 있다. `areas.REGIONS`·`region()`에 탭을 더하는 방식은 빌더 몫
- **가져올 종류** (Claude 판단): 롯데는 `C00903` 쇼핑뉴스 + `C00908` 문화/이벤트, 현대는 `01` 쇼핑뉴스 + `03` 문화이벤트. 사은·카드(`C00901`, `02`)와 Place&Eat(`C00927`)는 받지 않는다
- **매장 주소**: 7곳 주소는 각 매장 공식 페이지에서 찾아 코드에 둔다. 예: 의왕 `경기도 의왕시 바라산로 1(학의동)`(롯데 지점 페이지에서 확인)
- 새 출처 모듈은 `suwon_kids/sources/` 아래에 매장 계열별로(롯데·현대·AK·스타필드 브랜드) 나누는 것을 권한다. 기존 `starfield.py`의 쿠키 방식, `naver.py`의 기사 추출·날짜 대조, `http.new_jar()`를 다시 쓴다
- 테스트: 기존처럼 `tests/fixtures/`에 오늘 받은 응답을 저장해 파서 테스트를 한다. 네트워크 없이 돌아야 한다
- 응답 형식이 바뀌어 0건이 되면 조용히 빈 탭이 되지 않게 빌드 결과(`counts`/`errors`)에 매장별 건수를 남긴다

## 8. 빌더에게 맡기는 것

- 모듈·함수 이름, 파일 나누기, 탭 순서
- 고르기 규칙의 정확한 낱말 목록(위 예시는 출발점)
- 쪽 넘김 상한(요청 수를 과하게 늘리지 않는 선)
- 롯데 상세 링크 번호를 조각에서 읽는 방법. 못 찾으면 매장 쇼핑정보 페이지로 건다
